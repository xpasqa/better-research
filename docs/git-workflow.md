# Version control untuk kerja akademik

## Bootstrap

Pembuatan boilerplate awal yang diminta pengguna dapat diselesaikan dalam satu commit terverifikasi dan di-push ke main melalui fast-forward. Ini tidak menandakan gate penelitian lulus.

## Pekerjaan selanjutnya

- Periksa status dan remote sebelum perubahan/push; jangan menimpa perubahan pengguna.
- Untuk revisi substantif, gunakan branch pendek dan catatan tugas. GitHub Issue bersifat opsional kecuali pengguna/institusi menetapkannya; template tersedia.
- Kelompokkan commit menurut satu keputusan atau keluaran akademik. Catat alasan perubahan penting dalam decision/deviation log.
- Siapkan PR untuk perubahan substantif yang memerlukan review. Merge/publikasi mengikuti otorisasi pengguna yang sudah ada; jangan menambah permintaan izin yang sama.
- Pemeriksaan lokal, memo, draf, dan koreksi rutin dapat dilakukan dalam cakupan tugas tanpa persetujuan tambahan.
- Jangan force-push, menghapus riwayat, atau mengubah visibilitas repositori tanpa permintaan yang sesuai.
- Jangan mengubah sumber pada repositori lain. Gunakan origin proyek aktif untuk push.

## Pemeriksaan sebelum commit

Periksa perubahan, tautan lokal, konsistensi ID/sitasi, status template, serta data rahasia. Perubahan aturan harus ditinjau agar tidak diam-diam menurunkan kriteria akademik. Tidak perlu menjalankan pengujian statistik untuk perubahan dokumentasi.

## Definisi selesai

Hasil yang diminta tersedia dan diperiksa; sumber/batas bukti dicatat; status sesuai kegiatan nyata; perubahan tersimpan sesuai cakupan tugas. Commit atau PR selesai tidak sama dengan penelitian selesai.
